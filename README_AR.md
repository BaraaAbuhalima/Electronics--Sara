# فولت — إلكترونيات لأصحاب الأفكار

متجر إلكترونيات ثنائي اللغة، مبني باستخدام Next.js 16 وReact 19 وTypeScript وTailwind CSS 4 وأيقونات Lucide. اللغة الافتراضية هي الإنجليزية، ويمكن التبديل إلى العربية بواجهة من اليمين إلى اليسار وخط «تجوال» المحفوظ محلياً. تُحفظ اللغة والسلة في المتصفح. يشمل المتجر صفحة رئيسية، وكتالوجاً قابلاً للبحث والتصفية، وتفاصيل المنتجات، والأطقم والحزم، وسلة تراعي المخزون، وروابط للطلب عبر واتساب. لا توجد قاعدة بيانات أو حسابات عملاء أو بوابة دفع في هذا الإصدار.

## تشغيل الموقع

ثبّت Node.js بإصدار 20.9 أو أحدث. استُخدم الإصدار 24 أثناء التطوير. افتح الطرفية داخل مجلد المشروع `Electronics-Website` ونفّذ:

```bash
npm ci
npm run dev
```

افتح `http://localhost:3000` في المتصفح. أبقِ الطرفية مفتوحة ما دمت تعمل على الموقع، واضغط Ctrl+C لإيقافه. يُستخدم `npm install` بدلاً من `npm ci` عند الحاجة المقصودة إلى إنشاء ملف قفل جديد. لتشغيل نسخة الإنتاج:

```bash
npm run build
npm start
```

أوامر التحقق:

```bash
npm run validate:data
npm run typecheck
npm test
npm run test:e2e
```

تستخدم اختبارات المتصفح Chromium الموجود افتراضياً في `/usr/bin/chromium`. إذا كان في مسار آخر، حدّد المسار بمتغير `CHROMIUM_PATH`. يمكنك تثبيت Chromium بواسطة مدير الحزم في نظام التشغيل. تبدأ الاختبارات خادم التطوير تلقائياً إذا لم يكن قيد التشغيل. اختبارات منطق البيانات لا تحتاج إلى متصفح.

## إدارة المحتوى دون برمجة

ملفات JSON هي المصدر الوحيد لبيانات المتجر. افتحها بمحرر نصوص مثل VS Code. المنتجات في `data/products.json`، والفئات في `data/categories.json`، وبيانات المتجر والتواصل في `data/store.json`. أما عبارات الواجهة ففي `data/translations.json`.

المتصفح لا يستطيع تعديل هذه الملفات بشكل دائم، ولا توجد لوحة إدارة وهمية. عدّل الملفات داخل المشروع واحفظها. أثناء التطوير، حدّث الصفحة بعد الحفظ؛ وقد يحدث التحديث تلقائياً. أما الموقع المنشور فيحتاج إلى إعادة البناء والنشر بعد تعديل البيانات. احتفظ بنسخة احتياطية أو احفظ التغييرات في Git قبل التعديل.

### إضافة منتج خطوة بخطوة

1. افتح `data/products.json`. يحتوي الملف على قائمة تبدأ بـ `[` وتنتهي بـ `]`.
2. أضف فاصلة بعد آخر كائن موجود، ثم ألصق كائن المنتج الجديد قبل `]`. لا تستبدل القائمة كلها بكائن واحد.
3. اكتب معرّفاً فريداً وثابتاً في `id`، مثل `my-motor-002`. لا تغيّر المعرّفات المستخدمة في الأطقم والسلال المحفوظة دون مراجعة المراجع.
4. حدّد `type`: القيمة `component` لمكون منفرد، أو `kit` لطقم، أو `bundle` لحزمة.
5. اكتب الاسم والوصف بالإنجليزية في `name.en` و`description.en`.
6. اكتب الاسم والوصف بالعربية في `name.ar` و`description.ar`.
7. أدخل `price` و`discountPrice` الاختياري، واجعل `currency` مطابقاً لعملة المتجر؛ العملة الأولية `USD`. الأسعار أرقام دون رموز عملة.
8. أدخل رمز المخزون `sku` والكمية المتوفرة `stock` كعدد صحيح. الصفر يعني نفاد المخزون ويعطّل الإضافة إلى السلة.
9. اختر `categoryId` مطابقاً لمعرّف موجود في ملف الفئات.
10. ضع الصور في `public/images/products/` وأدرج مساراتها ضمن `images`.
11. أضف المواصفات المترجمة في `specifications` عند الحاجة.
12. احفظ الملف وشغّل `npm run validate:data`، ثم حدّث موقع التطوير. أعد البناء والنشر لنسخة الإنتاج.

الأمثلة التالية موجودة بالفعل ضمن المنتجات التجريبية. لإضافة منتج جديد بدلاً من تعديل منتج موجود، غيّر `id` و`sku` أولاً. ملفات الصور الواردة في الأمثلة موجودة في المشروع.

### شرح جميع خصائص المنتج

| الخاصية          | هل هي مطلوبة؟ | المحتوى                                                                              |
| ---------------- | ------------- | ------------------------------------------------------------------------------------ |
| `id`             | نعم           | معرّف نصي فريد وثابت.                                                                |
| `type`           | نعم           | إحدى القيم `component` أو `kit` أو `bundle`.                                         |
| `name`           | نعم           | كائن يحتوي `en` و`ar`، ولا يجوز ترك أي منهما فارغاً.                                 |
| `description`    | نعم           | وصف باللغتين، ويُستخدم أيضاً في تفاصيل المنتج.                                       |
| `price`          | نعم           | رقم غير سالب، ويفضّل ألا يتجاوز منزلتين عشريتين.                                     |
| `discountPrice`  | لا            | سعر مخفّض لا يتجاوز السعر الأصلي. احذف الخاصية أو استخدم `null` دون تخفيض.           |
| `currency`       | نعم           | رمز عملة من ثلاثة أحرف كبيرة يطابق عملة المتجر، مثل `USD`، وتدعمه Intl.NumberFormat. |
| `sku`            | نعم           | رمز المنتج المستخدم في المخزون.                                                      |
| `categoryId`     | نعم           | معرّف فئة موجودة.                                                                    |
| `images`         | نعم           | قائمة بمسار صورة واحدة على الأقل؛ الأولى رئيسية والبقية صور مصغرة في التفاصيل.       |
| `stock`          | نعم           | عدد صحيح لا يقل عن الصفر.                                                            |
| `specifications` | لا            | قائمة بكائنات `label` و`value`، ولكل منهما `en` و`ar`.                               |
| `featured`       | لا            | القيمة `true` تُدرج المنتج في المختارات. تعرض الرئيسية أول أربعة منتجات مطابقة.      |
| `newArrival`     | لا            | القيمة `true` تُدرجه ضمن «وصل حديثاً».                                               |
| `bestSeller`     | لا            | القيمة `true` تُدرجه ضمن الأكثر مبيعاً؛ لا يظهر التبويب إذا لم تتوفر بيانات.         |
| `components`     | للأطقم والحزم | قائمة مراجع `productId` وكميات صحيحة موجبة.                                          |

### تعديل منتج أو حذفه

ابحث عن الكائن بواسطة `id` وعدّله في مكانه. للحذف، احذف الكائن كاملاً مع الفاصلة المناسبة. راجع أولاً الأطقم والحزم التي تشير إليه وعدّل مراجعها. تعرض الواجهة تنبيهاً عند غياب مكون دون أن تتعطل، بينما يفشل التحقق حتى يُصحّح المرجع. عند استعادة سلة محفوظة تُحذف المنتجات المفقودة أو النافدة، وتُخفض الكميات التي تتجاوز المخزون.

## إضافة طقم

الطقم منتج واحد له سعر ومخزون ورمز وصورة خاصة به. تشير محتوياته إلى منتجات منفردة من النوع `component` موجودة مسبقاً. تعني `quantity: 2` وجود قطعتين داخل كل طقم، ولا تعني إنشاء سطرين في السلة. يُدار مخزون الطقم بشكل مستقل عن مكوناته، ولا يحجز المتصفح مخزوناً على الخادم.

## إدارة الصور

- صور المنتجات في `public/images/products/`، وصور الفئات في `public/images/categories/`. يمكن وضع الشعار في أي مسار محلي داخل `public/images/`.
- اختر أسماء بسيطة بأحرف لاتينية صغيرة ودون مسافات، مثل `motor-12v-front.webp`.
- الصيغ المدعومة: JPG وJPEG وPNG وWebP وAVIF وSVG. يُنصح بصور بحجم 1000 × 800 أو 1000 × 1000 بكسل وخلفية فاتحة سادة.
- اكتب `/images/products/motor-12v-front.webp` في JSON، دون كلمة `public`. يميّز Linux بين الأحرف الكبيرة والصغيرة.
- مثال صحيح لقائمة صور: `["/images/products/uno.jpg", "/images/products/uno.svg"]`.
- استخدم صوراً تملك حقوقها أو لديك ترخيص لاستخدامها. بعض الصور التجريبية رسوم للمكونات؛ صور أردوينو وESP32 وتراخيصها موثقة في `public/images/ATTRIBUTION.md`. استبدل الصور التوضيحية بصور مطابقة لمخزونك قبل البيع.
- تُعرض الصور بنسب متناسقة دون تمديد، ويُستخدم اسم المنتج كنص بديل باللغة المختارة. عند تعذّر تحميل صورة تظهر صورة إلكترونيات بديلة. يتحقق أمر فحص البيانات من المسارات ووجود الملفات.

## تحديث معلومات المتجر

عدّل `data/store.json`:

- `name.en` و`name.ar`: اسم المتجر باللغتين. `logo`: مسار الشعار المحلي.
- `tagline` و`description` و`about` و`copyright` و`contactNote`: كائنات نصية باللغتين. تظهر `contactNote` كملاحظة توضيحية للتواصل والنسخة التجريبية.
- `hero.eyebrow` و`hero.title` و`hero.description`: نصوص مقدمة الصفحة. استخدم `\n` داخل العنوان لبدء سطر جديد.
- `whatsapp`: رقمك الدولي متضمناً رمز الدولة، بالأرقام فقط ودون علامة الجمع أو المسافات. اتركه `""` لتعطيل روابط واتساب. أضف رقمك الحقيقي قبل استقبال الطلبات، ولا تستخدم رقم شخص آخر.
- `email`: بريدك الحقيقي. العنوان الافتراضي `hello@example.com` تجريبي ويجب استبداله. يفتح نموذج التواصل مسودة في تطبيق البريد لدى الزائر؛ لا يرسل إلى خادم ولا يضمن وصول الرسالة.
- `socials`: قائمة مثل `[{"name":"Instagram","url":"https://www.instagram.com/your_store/"}]` مع رابط حسابك الفعلي. القيمة `[]` تخفي الروابط الاجتماعية.
- `currency`: رمز العملة. عدّل عملة جميع المنتجات لتطابقه؛ لا يحوّل الموقع الأسعار تلقائياً بين العملات.

تحتوي رسالة واتساب على أسماء المنتجات باللغة المختارة، ورموزها، والكميات، وسعر الوحدة، ومجموع كل سطر، والإجمالي. يراجع العميل الرسالة ويرسلها بنفسه. أكّد التوصيل والتوفر والضرائب إن وجدت والسعر النهائي يدوياً. لا توجد حسابات شحن أو معالجة دفع في هذا الإصدار.

تحدد `hero.productIds` معرّفات منتجات صور المقدمة بالترتيب، وتحدد `hero.kitProductId` صورة طقم الشريط الترويجي. تظهر الصورة البديلة إذا حُذف منتج مشار إليه.

## أخطاء شائعة وحلولها

| المشكلة              | الحل                                                                                            |
| -------------------- | ----------------------------------------------------------------------------------------------- |
| فاصلة ناقصة          | ضع فاصلة بين الكائنات وبين الخصائص.                                                             |
| فاصلة زائدة          | احذف الفاصلة بعد آخر خاصية أو آخر عنصر في القائمة.                                              |
| علامات اقتباس ناقصة  | استخدم علامتَي اقتباس مستقيمتين حول المفاتيح والنصوص، ولا تضعهما حول الأرقام أو القيم المنطقية. |
| معرّف مكرر           | استخدم معرّفاً فريداً لكل منتج وفئة، وحافظ على ثبات المراجع.                                    |
| فئة غير موجودة       | انسخ `id` الصحيح من ملف الفئات دون تغيير.                                                       |
| مكون غير موجود       | أضف المنتج المنفرد أو صحّح `productId` أو أزل المرجع.                                           |
| كمية غير صحيحة       | استخدم أعداداً صحيحة موجبة للمكونات؛ يمكن أن يكون المخزون صفراً.                                |
| سعر غير صالح         | استخدم رقماً غير سالب، ولا تجعل التخفيض أكبر من السعر الأصلي.                                   |
| صورة لا تظهر         | راجع اسم الملف وحالة الأحرف ووجوده وبداية المسار `/images/`.                                    |
| التعديل لا يظهر      | احفظ الملف وحدّث صفحة التطوير، أو أعد البناء والنشر لنسخة الإنتاج.                              |
| الطلب غير متاح       | أضف رقم واتساب الدولي الحقيقي بالأرقام فقط في ملف المتجر.                                       |
| تطبيق البريد لا يفتح | انسخ البريد الظاهر وراسله من تطبيقك. يلزم إعداد تطبيق بريد يدعم الروابط.                        |

بعد كل تعديل، شغّل `npm run validate:data`. يفحص الأمر صياغة JSON والمعرّفات والترجمات المطلوبة والأنواع ومراجع الفئات والمكونات والكميات والأسعار والمواصفات وتطابق العملات ومسارات الصور ووجود ملفاتها. ينفّذ `npm run build` هذا الفحص أولاً. يضع VS Code أيضاً خطوطاً تحت أخطاء الصياغة. أصلح أول خطأ وأعد الفحص. يظهر تنبيه في الواجهة للبيانات التي يمكن قراءتها لكن بنيتها غير صحيحة؛ أما خطأ صياغة JSON فيجب تصحيحه حتى يتمكن التطبيق من البناء. لا تكتب تعليقات داخل ملفات JSON.

## البنية والتوسع مستقبلاً

يوفر `src/services/catalog.ts` الدوال `getAllProducts` و`getProductById` و`getProductsByCategory` و`getFeaturedProducts` و`getAllCategories` و`getKitComponents` و`getStoreInfo`. يمكن استبدال هذه الطبقة لاحقاً بواجهة API. لا تتضمن مكونات العرض سجلات المنتجات أو بيانات التواصل. يتولى `src/services/cart.ts` تنظيف السلة وحساب الإجمالي بالسنتات الصحيحة. ويُستخدم `src/services/validation.ts` في التطبيق وفي فحص البيانات قبل البناء.

يستخدم الإصدار الحالي روابط الأجزاء `#products` و`#kits` و`#product/PRODUCT_ID` مع نوافذ لتفاصيل المنتجات. يمكن إضافة صفحات مستقلة للمنتجات وتحسين ظهورها في البحث، ولوحة إدارة، ورفع صور، وحسابات، ومخزون، ودفع، وإدارة طلبات لاحقاً؛ هذه الميزات ليست محاكاة في النسخة الحالية. لإضافة لغة، وسّع نوع `Language` والترجمات وجميع البيانات المترجمة ومبدّل اللغة وتنسيق الأرقام وإعدادات الخط والاتجاه.

الدليل الإنجليزي في [README.md](README.md).
